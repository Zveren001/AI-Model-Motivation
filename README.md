# Мотивационный аккаунт

Instagram-аккаунт с короткими мыслями на однотонном фоне. Работает сам: сервер берёт следующую цитату, рисует картинку и публикует по расписанию. Участие не требуется.

**Instagram:** [@mono.motiv](https://instagram.com/mono.motiv)
**Threads:** тот же аккаунт
**Репозиторий:** [github.com/Zveren001/AI-Model-Motivation](https://github.com/Zveren001/AI-Model-Motivation)

## Как это устроено

Картинки **не генерируются нейросетью**. Они рисуются программно за доли секунды: однотонный фон, текст по центру, кегль подбирается под длину цитаты. Ни моделей, ни ожидания, ни отказов, ни счетов за API.

Фон чередуется строго: белый → чёрный → белый → чёрный, каждую публикацию.

Формат при этом идёт парами — по два ролика, потом две картинки. Иначе никак:
если через один менять и цвет, и формат, периоды совпадут и цвет намертво
прилипнет к формату — все ролики станут одного цвета, все картинки другого.
Приоритет отдан цвету, поэтому в сетке нет двух одинаковых плиток подряд.

Позиция в цикле пишется в журнал полем `cycle` и считается от последней записи,
а не от сквозного счётчика: ручная публикация и удаление поста из ленты счётчик
сдвигают, а цикл должен следовать за тем, что зритель видит на самом деле.

Ролики собираются так же программно: те же цитата, шрифт и палитра, но в вертикали 1080x1920 и с анимацией. Эффектов десять, они идут по кругу со сдвигом на каждом обороте — иначе эффект намертво срастался бы с одной темой. Шесть секунд рендера, девять секунд с кодированием на одном ядре.

Звук берётся из `assets/audio`: под белый кадр `white.mp3`, под чёрный `black.mp3`, а к эффектам с печатью подмешивается стук клавиш `write.mp3`. Все дорожки по семь секунд — отсюда и длина ролика.

Публикация занимает от 12 секунд для картинки до минуты для ролика. Материал уходит в хранилище `nika-media`, папка `motivation/`, оттуда его забирает Instagram, локальная копия сразу удаляется.

Threads отключён после бана 27.08.2026 — токен в `.env` пуст, код проверяет его перед отправкой и молча пропускает. Ролики туда не ушли бы в любом случае: Threads принимает только картинки и карусели.

## Работа с базой цитат

```
cd tools
python add_quotes.py --stats    статистика: сколько осталось, на сколько хватит
python add_quotes.py --lint     проверка текстов на типовые огрехи
```

Пополнить:

```python
import add_quotes
add_quotes.add([("Текст цитаты", "тема")])
```

Дубли отсеиваются автоматически по нормализованному тексту — регистр, пунктуация и ё/е не считаются различием.

**Правила для новых цитат:** без авторства, без точки в конце, нейтральная тематика — никакой политики, религии, веществ. Про свободу и границы — только в личном смысле, о работе и отношениях.

## Локальная проверка

```
cd tools
python render.py "Текст цитаты" 0 ../output/test.jpg   # 0 белый фон, 1 чёрный
python reel.py "Текст цитаты" 0 ../output/test.mp4     # номер задаёт эффект и тему
python autopost.py --dry-run                           # что ушло бы, без отправки
python autopost.py --kind=reel --now                   # разово опубликовать ролик
```

Нужны Pillow и ffmpeg в `PATH`. Свой путь к ffmpeg задаётся ключом `FFMPEG` в `.env`.

Важно: **локальная база и серверная живут отдельно**. Публикует сервер, там же обновляются флаги использования. Локально правится только код и тексты, дальше `git push` и `git pull` на сервере.

## Обслуживание

Практически никакого. Раз в 60 дней перевыпустить токены — иначе публикация молча встанет с ошибкой доступа. Токенов два, инстаграмный и отдельный от Threads:

```
cd /opt/motivation/tools
../venv/bin/python threads_refresh_token.py
```

Токен Instagram продлевается через интерфейс Meta.

Обновить код на сервере:

```
cd /opt/motivation && git pull
```

Подробности, диагностика и логи — [docs/vps-setup.md](docs/vps-setup.md).

## Особенности, о которых стоит помнить

**Время задано в UTC, и это принципиально.** `CRON_TZ=Europe/Moscow` в Ubuntu не работает — переменная молча игнорируется, и первые сутки посты выходили на три часа позже задуманного. В расписании стоят 21:00, 03:00, 09:00 и 15:00 UTC — это полночь, шесть утра, полдень и шесть вечера по Москве.

Полуночный слот в UTC приходится на предыдущий календарный день, и это нормально: скрипт считает московское время сам и записывает пост уже следующей датой.

Внутри скрипта время тоже считается самостоятельно, с фиксированным смещением UTC+3: полагаться на системное нельзя, иначе в 06:00 МСК он увидит 03:00 и решит, что слот не наступил.

**Разброс времени.** Час задаёт cron, минуты внутри часа — сам скрипт: перед публикацией он выжидает от 15 до 30 минут случайно. Расписание секунда в секунду читается как автопостинг и площадкой, и живым человеком. Ручной запуск паузу пропускает ключом `--now`, а блокировка рассчитана на час, чтобы её пережить.

**Чередование считается от последнего поста, а не от чётности счётчика.** Ручной запуск с ключом `--kind` сдвигает сквозной счётчик, чётность перестаёт совпадать с лентой, и следующий пост вышел бы того же типа. Тема и эффект тоже берутся по номеру внутри своего типа: делить общий счётчик пополам нельзя по той же причине.

**ffmpeg на сервере — статический бинарник** в `/usr/local/bin`, без пакетов и зависимостей: машина делит ядро с VPN, и тянуть туда пол-системы ради кодека незачем.

**Соседство с VPN.** На той же машине работает WireGuard. Публикация запускается через `nice` и `ionice`, чтобы уступать ему дорогу. По замерам нагрузки нет вообще: load average 0.06, память не меняется.

**Метка ИИ не нужна.** В отличие от проекта с виртуальным человеком: здесь текст на однотонном фоне, он никого не изображает и ввести в заблуждение не может.

**`.env` на сервере отдельный.** В git он не попадает, поэтому новые ключи — например токен Threads — дописываются на VPS руками, `git pull` их не принесёт.
