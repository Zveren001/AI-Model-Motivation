# Мотивационный аккаунт

Instagram-аккаунт и YouTube-канал с короткими мыслями. Работает сам: сервер берёт цитату, рисует картинку или собирает ролик с голосом и видеорядом и публикует по расписанию. Участие не требуется.

**Instagram:** [@mono.motiv](https://instagram.com/mono.motiv)
**YouTube:** [@MonoMotivation69](https://www.youtube.com/@MonoMotivation69)
**Threads:** тот же аккаунт, забанен 27.08.2026
**Репозиторий:** [github.com/Zveren001/AI-Model-Motivation](https://github.com/Zveren001/AI-Model-Motivation)

Стратегия, диагноз плато и критерии — [docs/strategy.md](docs/strategy.md).

## Состояние

| | |
|---|---|
| Цитат в базе | 1495, все уникальные, 125 тем |
| Расписание | 09:00 и 12:00 картинки, 18:00 и 21:00 ролики, по Москве, плюс разброс 15-30 минут |
| Форматы | картинка 1080x1080 с текстом на однотонном фоне; ролик 1080x1920 на 7-11 секунд: клип из стока, голос, слова загораются в ритм речи |
| Площадки | Instagram, ролики дублируются на YouTube; Threads отключён |
| Статистика | `youtube_stats.py` раз в сутки в 08:30 по Москве, после перевыпуска токена |
| Где работает | VPS в Амстердаме, `/opt/motivation` |

Часы задаются в двух местах и должны совпадать: `SLOTS` и `REEL_SLOTS` в `.env` — по Москве, строки в `deploy/motivation.cron` — в UTC.

## Как это устроено

**Картинки** рисуются программно за доли секунды: однотонный фон, текст по центру, кегль под длину. Фон чередуется белый → чёрный от последней картинки в журнале: ручная публикация и удаление поста счётчик сдвигают, а чередование должно следовать за тем, что зритель видит в ленте.

**Ролик** собирается из той же цитаты, что могла бы уйти картинкой:

1. Светлана из edge-tts читает цитату и короткий призыв и отдаёт тайминги слов.
2. По теме цитаты из стока Pexels берётся вертикальный клип, кэшируется в `footage/` и не повторяется месяц.
3. Цитата стоит в кадре целиком с нулевой секунды: непроизнесённые слова приглушены, произнесённое загорается белым. У ролика нет пустого начала, а у YouTube пустой обложки.
   Момент загорания оформлен одним из пяти эффектов: слово просто загорается, выезжает снизу, вспыхивает крупнее, светится, либо строка загорается целиком. Эффекты идут по кругу и сравниваются статистикой наравне с темами и призывами.
4. В конце внизу появляется призыв: «Напиши в комментариях», «Подпишись» или «Лайк, если про тебя». Варианты идут по кругу, пока по каждому не наберётся статистика.
5. Последние полсекунды цитата плавно гаснет обратно в приглушённую, поэтому финальный кадр совпадает с первым и повтор в ленте склеивается без рывка.
6. ffmpeg за один проход: клип обрезается под 1080x1920, затемняется с виньеткой, сверху субтитры, звук — голос и тихая подложка из `assets/audio`.

Ролик длится 7–11 секунд, столько же, сколько занимает речь. Без голоса или без клипа он не собирается, слот пропускается с записью в лог: лучше пропуск, чем немой слайд.

**Тип публикации привязан к слоту:** вечерние слоты из `REEL_SLOTS` отдают ролики, остальные — картинки. Ролики стоят вечером не случайно: первые часы после выхода решают, пойдёт ли Shorts дальше тестовой порции показов.

**Что решает статистика.** Раз в сутки `youtube_stats.py` собирает по каждому ролику просмотры, лайки, комментарии и вовлечённые просмотры в `stats.json`. По ним `autopost.py` выбирает призыв, эффект и тему цитаты: призывы и эффекты идут по кругу, пока по каждому не наберётся шесть роликов с оценкой, дальше чаще выходит лучший; тема в 70 % случаев берётся из шести лучших, в 30 % — наугад, а тема двух последних роликов пропускается, иначе выбор залипает на одной. Картинки идут по порядку базы.

Публикация занимает от 12 секунд для картинки до пары минут для ролика. Материал уходит в хранилище `nika-media`, папка `motivation/`, оттуда его забирает Instagram, локальная копия сразу удаляется. На YouTube ролик уходит с заголовком-цитатой, описанием из цитаты, ссылкой на сток, хэштегом темы и языком `ru`.

Threads отключён после бана 27.08.2026 — токен в `.env` пуст, код проверяет его перед отправкой и молча пропускает.

## Работа с базой цитат

```
cd tools
python add_quotes.py --stats       сколько цитат осталось и на сколько хватит
python add_quotes.py --lint        проверка текстов на типовые огрехи
python add_quotes.py --sync-used   отметить использованные по журналу (на сервере после git pull)
```

Пополнить обычными цитатами:

```python
import add_quotes
add_quotes.add([("Текст цитаты", "тема")])
```

Убрать кривую цитату:

```python
add_quotes.remove([98, 128])
```

Дубли отсеиваются автоматически по нормализованному тексту — регистр, пунктуация и ё/е не считаются различием.

**Правила для текстов.** Без авторства, без точки в конце, нейтральная тематика — никакой политики, религии, веществ. Про свободу и границы — только в личном смысле. Текст должен читаться вслух за пять-семь секунд и быть понятным с первого раза: цитата идёт и в картинку, и в ролик голосом.

## Локальная проверка

```
cd tools
python render.py "Текст цитаты" 0 ../output/test.jpg           # 0 белый фон, 1 чёрный
python reel.py --id=63 ../output/test.mp4 --cta=comment         # ролик из цитаты базы
python reel.py --id=63 ../output/test.mp4 --effect=slova_snizu  # выбрать эффект вручную
python reel.py --id=63 ../output/test.mp4 --clip=../footage/8472307.mp4    # на клипе из кэша
python voice.py "Текст" ../output/voice.mp3                    # озвучка с таймингами
python footage.py тревога                                      # клип под тему
python autopost.py --dry-run --slot=18                          # что ушло бы в ролик, без отправки
python autopost.py --kind=reel --now                           # разово опубликовать ролик
python youtube_stats.py --summary                              # сводка из stats.json
```

Важно: **локальная база и серверная живут отдельно**. Публикует сервер, там же обновляются флаги использования. Локально правится только код и тексты, дальше `git push` и обновление на сервере.

## Обслуживание

Раз в 60 дней перевыпустить токен Instagram через интерфейс Meta — иначе публикация молча встанет с ошибкой доступа. Токен YouTube живёт, пока приложение в Production.

**Обновить код на сервере.** База цитат на сервере изменена флагами использования, поэтому перед `git pull` её надо вернуть к версии из git, а после — восстановить флаги по журналу:

```
cd /opt/motivation
git checkout -- quotes/quotes.json
git pull
cd tools && ../venv/bin/python add_quotes.py --sync-used
```

**Обновить расписание** — только через `sed`, иначе файл с CRLF отвергается целиком:

```
sed 's/\r$//' /opt/motivation/deploy/motivation.cron > /etc/cron.d/motivation
chmod 644 /etc/cron.d/motivation
systemctl restart cron
```

**Перевыпустить токен YouTube** с правами на статистику — [docs/youtube-token.md](docs/youtube-token.md). До этого `youtube_stats.py` пишет в лог, что прав нет, и выходит; публикация не страдает.

Подробности, диагностика и логи — [docs/vps-setup.md](docs/vps-setup.md).

## Особенности, о которых стоит помнить

**Время задано в UTC, и это принципиально.** `CRON_TZ=Europe/Moscow` в Ubuntu не работает — переменная молча игнорируется. В расписании стоят 06:00, 09:00, 15:00 и 18:00 UTC — это 09:00, 12:00, 18:00 и 21:00 по Москве; сбор статистики в 05:30 UTC.

Внутри скрипта время тоже считается самостоятельно, с фиксированным смещением UTC+3: полагаться на системное нельзя, иначе в 09:00 МСК он увидит 06:00 и решит, что слот не наступил.

**Разброс времени.** Час задаёт cron, минуты внутри часа — сам скрипт: перед публикацией он выжидает от 15 до 30 минут случайно. Ручной запуск паузу пропускает ключом `--now`, а блокировка рассчитана на час, чтобы её пережить вместе с озвучкой, скачиванием клипа и кодированием.

**Ролик зависит от двух внешних сервисов.** Голос приходит из edge-tts, клип из Pexels. Озвучка повторяется три раза с паузами; клип при сбое стока берётся из кэша, а при пустом кэше слот пропускается. Pexels отвечает 403 на запросы без заголовка браузера — он выставляется в `footage.py`.

**ffmpeg запускается из временной папки.** Субтитры и шрифт передаются фильтру по коротким именам: абсолютный путь с двоеточием и пробелами требует двухуровневого экранирования и на Windows ломается.

**Оценка ролика — просмотры на первом замере старше суток**, а не текущие. Метрику «выбрали просмотр» API не отдаёт, её заменяет доля вовлечённых просмотров.

**ffmpeg на сервере — статический бинарник** в `/usr/local/bin` с libass, без пакетов: машина делит ядро с VPN.

**Соседство с VPN.** На той же машине работает WireGuard. Публикация запускается через `nice` и `ionice`. Ролик собирается около минуты на одном ядре.

**Метка синтетического контента не ставится.** Голос читает текст от лица канала, никого не изображает и не показывает вымышленных событий; по правилам YouTube такая озвучка раскрытия не требует.

**Кегль в ASS и в Pillow — разные вещи.** libass рисует ровно три четверти той ширины, которую даёт Pillow тем же числом; замер сделан на локальной машине и на сервере и совпал до пикселя. Поправка `SCALE` в `captions.py` держит координаты слов на месте, без неё слова разъезжаются.

**Петля важнее длины.** Восьмисекундные ролики держали досмотр 94–141 %, потому что зритель проходил их дважды; двадцатидвухсекундные упали до 54–72 % и потеряли раздачу. Поэтому ролик длится ровно столько, сколько занимает речь, и заканчивается тем же кадром, с которого начался.

**`.env` на сервере отдельный.** В git он не попадает, поэтому новые ключи — `REEL_SLOTS`, `PEXELS_API_KEY`, `VOICE_RATE` — дописываются на VPS руками, `git pull` их не принесёт. Кириллицу на сервер только файлами, через plink — латиницу.
