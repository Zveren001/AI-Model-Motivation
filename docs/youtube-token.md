# Перевыпуск токена YouTube с правами на статистику

Токен, выпущенный при подключении канала, умеет только загружать ролики.
Для сбора статистики (`youtube_stats.py`), комментариев автора и плейлистов
нужны ещё два права, а права токену выдаются в момент выпуска. Поэтому токен
выпускается заново. Делается один раз, минут за десять.

| Право | Зачем |
|---|---|
| `youtube.upload` | загрузка роликов, было и раньше |
| `youtube.force-ssl` | просмотры, лайки и комментарии по роликам; позже комментарии автора, плейлисты, описание канала |
| `yt-analytics.readonly` | вовлечённые просмотры, досмотр, подписки с ролика |

Старый токен продолжает работать, пока не выпущен новый: публикация в это
время не останавливается.

## 1. Включить YouTube Analytics API

[console.cloud.google.com](https://console.cloud.google.com), проект
`poised-rock-507006-u8`.

**APIs & Services → Library**, в поиске «YouTube Analytics API», открыть,
нажать **Enable**. YouTube Data API v3 уже включён, его не трогать.

Без этого шага запрос статистики вернёт `accessNotConfigured`, а скрипт
напишет «API не включён в проекте Google Cloud».

## 2. Экран согласия не трогать

Права на экране **Data Access** прописывать не нужно: 04.09.2026 токен
с тремя правами выпущен без этого, Google просто показывает окно
«приложение не проверено». Баннеры «requires verification» можно игнорировать.

Раздел **Audience** тоже не трогать: статус Publishing должен остаться
**In production**. В режиме Testing Google отзывает refresh-токен через семь
дней, и публикация встанет.

## 3. Выпустить токен

Локально, на машине с браузером:

```
cd tools
python youtube_auth.py
```

Откроется согласие Google. Выбрать аккаунт `mono.motivation69@gmail.com`.
Приложение не проверено, поэтому будет предупреждение: **«Дополнительно» →
«Перейти на страницу»**. На экране прав отметить все три галочки, иначе
токен выйдет без нужного права и всё придётся повторять.

Скрипт запишет `YT_REFRESH_TOKEN` в локальный `.env` и напечатает
«Токен получен и записан в .env».

## 4. Перенести токен на сервер

`.env` в git не попадает, поэтому значение переносится руками. Токен
латиница, через plink можно:

```
nano /opt/motivation/.env
```

Заменить строку `YT_REFRESH_TOKEN=...` на новое значение из локального `.env`.

## 5. Проверить

На сервере:

```
cd /opt/motivation/tools
../venv/bin/python youtube_stats.py --check
```

Скрипт печатает права токена и пишет «Прав достаточно для статистики».
Если пишет «Не хватает» — на шаге 3 не была отмечена галочка, повторить
с шага 3.

Затем первый сбор:

```
../venv/bin/python youtube_stats.py
```

Появится `stats.json` и таблица по роликам. Дальше сбор идёт сам, по cron
в 08:30 по Москве, и autopost.py начинает учитывать статистику при выборе тем.

## Если что-то пошло не так

- **«нет прав у токена»** в логе — токен старый или без галочки, шаг 3.
- **«API не включён»** — шаг 1.
- **Google не вернул refresh_token** — согласие прошло без `prompt=consent`;
  отозвать доступ приложению на [myaccount.google.com/permissions](https://myaccount.google.com/permissions)
  и повторить шаг 3.
- **Ролики перестали загружаться** после перевыпуска — в `.env` на сервере
  токен скопирован с обрезанным концом; сверить длину с локальным.
